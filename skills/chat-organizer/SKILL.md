# 聊天整理助手
使用本 Skill 自带的 scripts/organize.py。将下文的入口替换成此文件所在目录下的脚本绝对路径。使用已验证的 Python 3.14。首次运行执行 doctor；缺项按准确原因处理，不重置数据、不盲目重启。

## 命名与报告
“整理20条”授权读取、分析、直接改名，不授权创建项目或移动聊天。未给数量默认20，支持1至20。
执行：`py -3.14 <入口> scan --count 20`。
保存返回的 session_id，读取逐条报告，展示原题、新题、摘要、分组建议、理由、执行状态，以及已有项目、新项目、杂聊保留等汇总。不能只报总数。
回看执行 `report --session-id ID`，不会重调模型。
中断续接用 `scan --count 原数量 --session-id ID`；先查已有回执，不换编号重发失败批次，不解除锁定，不用旧记录凑数。
模型会读取选中聊天的可见正文；本地不是零用量或完全离线。标题与分组建议同批生成。

## 确认后归类
用户确认具体报告或提出调整后，另存批准文件，保留 session_id 和 review_digest；approved=true，user_confirmation 必须记录真实用户确认。只涉及该会话成功命名的聊天，禁止伪造批准。
destination 为已有项目ID、keep、null 或 new:项目名。杂聊默认 keep；只有用户确认移出原项目才设 null。允许部分批准。
已有项目执行：`apply --session-id ID --approval 批准文件绝对路径`。
新项目执行前阅读 references/projects-and-recovery.md。核对同名项目及真实根目录，准备 roots 文件，再运行 prepare-projects。后端创建和桌面登记分开验收；用原始ID复用项目，不重建。没有离线修复授权时不能启动修复。
完成后逐条报告实际结果。归类读取缓存，不重新分析。

## 保护与交付
- 所有已处理记录持续跳过；升级不能清空数据目录。用户点名旧聊天修改作为独立任务。
- 只使用安装的原版官方工具和执行器真实环境，不输出连接凭据，不修改插件。
- 写前意图、冲突检查、独立回读、保护置顶；失败保留证据，核查实际状态后再决定，不自动重放。
- 不操作屏幕，不排程，不直接写生产SQLite；离线配置修复仅在明确授权、版本与守卫都通过后执行。
- 区分建议、已执行、后端创建、原生目录可见和截图验收；不得混称。
- 报告放配置指定的正式输出目录。先给目录绝对路径，再给逐条报告链接。遵循用户位置偏好。
- 环境与缓存说明见 references/runtime.md。
